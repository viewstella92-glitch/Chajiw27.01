# 拆句 江湖 — ตำรับยุทธ์แยกประโยคจีน

เว็บเรียนภาษาจีนธีมยุทธภพสำหรับฝึกแยกคำ วิเคราะห์ประโยค สะสมคำศัพท์ และทบทวนคำศัพท์ โดยออกแบบให้ใช้งานบนมือถือและคอมพิวเตอร์ได้

## ฟีเจอร์

- แยกคำ + พินอิน + วรรณยุกต์ + คำแปล + ไวยากรณ์ + ระดับ HSK โดยประมาณ
- แยกส่วนประกอบตัวอักษร + คำอื่นที่มีตัวอักษรนี้อยู่
- วาดตัวจีน + ทายลายมือ
- 🔊 ออกเสียงคำศัพท์และประโยคตัวอย่างด้วย Web Speech API ของเบราว์เซอร์ ไม่ต้องใช้โควตา AI
- บันทึกคำศัพท์ + เล่นแฟลชการ์ด พร้อมระบบทบทวนแบบ spaced repetition
- แดชบอร์ด: ขั้นภูมิ (境界) ตามจำนวนคำที่สะสม, สถิติการเรียน, ปฏิทินต่อเนื่อง, คำที่ครบกำหนดทบทวน และสถิติรูปแบบไวยากรณ์
- ควิซจากคำศัพท์ที่บันทึกไว้ โดยสร้างคำถามฝั่ง client
- ฝึกแต่งประโยค: สุ่มคำจากคลังคำศัพท์ แล้วให้ AI ตรวจและแก้ไข
- เก็บข้อมูลบน Supabase แบบ single-user โดยไม่ต้องมีระบบ login และใช้ localStorage เป็นข้อมูลฝั่งอุปกรณ์
- การลบคำศัพท์ใช้ deletion tombstones และการแก้ไขคำใช้ updatedAt เพื่อป้องกันข้อมูลจากอุปกรณ์อื่นย้อนกลับมาทับข้อมูลใหม่กว่า

## AI และ API

### Groq
ใช้กับฟีเจอร์ข้อความ:
- `/api/segment` — แยกคำ + วิเคราะห์ไวยากรณ์
- `/api/breakdown` — แยกส่วนประกอบตัวอักษรและหาคำที่เกี่ยวข้อง

ทั้งสอง route เรียกผ่าน `lib/llm.js` และลอง Groq 2 โมเดลตามลำดับเมื่อโมเดลแรกใช้ไม่ได้หรือถูก rate limit

### Gemini
ใช้เฉพาะ:
- `/api/recognize` — ทายตัวอักษรจีนจากภาพลายมือ

## รันทดสอบในเครื่อง

1. ติดตั้ง dependencies:
   ```
   npm install
   ```
2. สร้าง `.env.local` และใส่:
   ```
   GEMINI_API_KEY=your_key_here
   GROQ_API_KEY=your_groq_key_here
   NEXT_PUBLIC_SUPABASE_URL=your_supabase_url
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
   ```
3. รัน:
   ```
   npm run dev
   ```
4. เปิด `http://localhost:3000`

## Deploy ขึ้น Vercel

ตั้ง Environment Variables บน Vercel อย่างน้อย:
- `GEMINI_API_KEY`
- `GROQ_API_KEY`
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

ไม่ควร commit `.env.local` หรือ secret key ขึ้น GitHub

## โครงสร้างไฟล์

- `app/page.js` — หน้าหลักและ UI ของแอป
- `app/api/segment/route.js` — แยกคำและวิเคราะห์ประโยคผ่าน Groq
- `app/api/breakdown/route.js` — วิเคราะห์ส่วนประกอบตัวอักษรผ่าน Groq
- `app/api/recognize/route.js` — ทายลายมือผ่าน Gemini Vision
- `lib/llm.js` — ตัวกลางเรียก Groq สำหรับงานข้อความ
- `lib/cloud.js` — อ่าน/บันทึกข้อมูล single-user บน Supabase

ไม่มี `app/api/related/route.js` แยกต่างหากแล้ว เพราะการหาคำที่เกี่ยวข้องถูกรวมอยู่ใน `/api/breakdown`

## ข้อมูลและการซิงก์

ข้อมูลหลักถูกเก็บใน localStorage เพื่อให้เว็บทำงานได้ทันทีบนอุปกรณ์นั้น และเมื่อเปิดใช้งาน Supabase เว็บจะอ่าน/เขียนข้อมูลของผู้ใช้คนเดียวกันผ่าน record เดียว

การ sync คำศัพท์ใช้ `updatedAt` รายคำ และ deletion tombstones (`deletedAt`) เพื่อให้:
- การแก้ไขจากอุปกรณ์หนึ่งไม่ถูกข้อมูลเก่าจากอีกอุปกรณ์ทับ
- คำที่ลบแล้วไม่ถูกดึงกลับมาเพียงเพราะยังมีสำเนาเก่าอยู่บนอีกอุปกรณ์

> หมายเหตุ: ระบบนี้เป็น single-user โดยตั้งใจ ไม่มี login ดังนั้นผู้ที่เข้าถึงเว็บเดียวกันและมี Supabase config เดียวกันจะใช้ข้อมูล cloud ชุดเดียวกัน

## หมายเหตุด้านโครงสร้างโค้ด

`app/page.js` ยังมีขนาดค่อนข้างใหญ่และรวม state, logic และ UI หลายส่วนไว้ในไฟล์เดียว ปัจจุบันจึงถือเป็น technical debt ที่ควรทยอยแยกเป็น components/hooks เมื่อมีการปรับฟีเจอร์รอบใหญ่ เพื่อหลีกเลี่ยงการ refactor ครั้งใหญ่ที่เสี่ยงทำให้ฟีเจอร์ที่ทำงานอยู่พัง

## ติดหน้าจอหลัก (PWA)

เว็บมี `manifest.json` และไอคอนในตัว สามารถเปิดผ่าน Safari (iOS) หรือ Chrome (Android) แล้วเพิ่มไปที่หน้าจอโฮมได้
